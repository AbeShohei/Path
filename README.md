## 🎯 概要

**Path**は、京都観光に特化したAI観光ナビゲーションアプリです。

公共交通オープンデータと人流オープンデータを活用し、「混雑を避けた快適な観光」と「移動時間を楽しむAIガイド」を提供します。

### コアコンセプト

| コンセプト | 説明 |
|:---:|:---|
| **Travel as a Story** | 移動時間を、AIが語る土地の物語（歴史・文化）で彩る |
| **Data Driven** | オープンデータを活用した混雑回避と正確なルート案内 |

## 💡 開発のきっかけ・背景

### 京都観光の現状

京都は年間5,000万人以上が訪れる世界有数の観光都市です。しかし、以下の課題が顕在化しています：

1. **オーバーツーリズム問題**
   - 特定の観光地（清水寺、伏見稲荷など）への観光客の集中
   - 混雑による観光体験の質の低下
   - 地域住民の日常生活への影響

2. **移動時間の「もったいなさ」**
   - バスや電車での移動時間は「空白の時間」になりがち
   - せっかくの京都の街並みを見ても、その歴史や背景を知る機会がない

3. **情報格差**
   - 外国人観光客や初めての訪問者は、穴場スポットを見つけにくい
   - リアルタイムの混雑情報が不足

### 解決に向けた着想

> 「公共交通のオープンデータと人流データを組み合わせれば、**混雑を避けながら快適に観光できるルート**を提案できるのではないか？」

> 「さらに、移動中にAIが**その場所の歴史や文化を語ってくれれば**、移動時間そのものが観光体験になるのではないか？」

この2つの着想から、**Path**の開発がスタートしました。

## 🔍 課題とアプローチ

### 課題1: 混雑情報のリアルタイム性と相対化

| 課題 | アプローチ |
|:---|:---|
| **データの偏り** | 京都市全体の人流データを使うと、繁華街と山間部の格差が激しすぎる |
| **相対的な評価** | **観光スポットが存在するメッシュのみ**を母集団として抽出し、偏差値（T-score）を算出 |

**混雑度判定ロジック (実装: `services/humanFlowService.ts`)**:

観光スポットがあるエリアの人流データのみを抽出し、以下の偏差値基準で5段階に分類することで、**全スポットを約20%ずつ均等に**振り分けています。これにより、「どこもかしこも混雑」という状態を防ぎ、相対的に空いているスポットを見つけやすくしています。

- **Lv 1 快適**: 偏差値 ～42 (下位 約21%)
- **Lv 2 やや快適**: 偏差値 42～48 (次点 約21%)
- **Lv 3 通常**: 偏差値 48～52 (中間 約16%)
- **Lv 4 やや混雑**: 偏差値 52～58 (次点 約21%)
- **Lv 5 混雑**: 偏差値 58～ (上位 約21%)

### 課題2: 移動体験の最適化範囲

| 課題 | アプローチ |
|:---|:---|
| **地下鉄の限界** | 地下鉄は移動が早いが、**車窓からの景色が見えない**ため「移動自体を観光にする」コンセプトに不向き |
| **バスへの集中** | あえて**「京都市バス」**に対象を絞ることで、路地裏や歴史的な街並みを眺めながらの移動体験を最大化 |

本来はあらゆる交通手段を網羅すべきですが、本アプリの「Travel as a Story（移動を物語に）」というコンセプトを体現するため、車窓からの風景情報とAIガイドがリンクしやすい**バス移動**をコア体験として設計しました。

### 課題3: AIハルシネーション（嘘）の抑止

| 課題 | アプローチ |
|:---|:---|
| **事実と異なる生成** | AIにゼロから解説を作らせると、存在しない歴史を語るリスクがある（ハルシネーション） |
| **RAGアーキテクチャ** | **京都市オープンデータの公式説明文**をプロンプトに埋め込み、AIの役割を「事実の生成」から「表現の変換」に限定 |

**AIへの指示（プロンプト設計）**:
AIには「新しい情報を付け足すこと」ではなく、以下の2点のみを厳格に指示しています。
1. **文体変換**: 「〜である」調の硬い説明文を、ガイド風の「〜ですね」調の語り口に変換
2. **平易化**: 専門用語や難解な歴史用語を、観光客でも直感的に分かる言葉に噛み砕く

これにより、情報の正確性をオープンデータで担保しつつ、AIの表現力で情緒的な価値を付加することに成功しています。

## ✨ 主な機能

### 1. 混雑回避スポット検索

- 現在地周辺の観光スポットを**混雑度順**に表示
- 5段階の混雑フィルター（快適〜混雑）
- 時間帯切替による混雑予測表示

### 2. ルート検索・ナビゲーション

- **バス + 徒歩**の複合ルート検索
- **京都市営地下鉄**対応
- 出発・到着時刻、乗換駅の詳細表示
- 途中駅のアコーディオン表示

### 3. AIガイド（移動中のナレーション）

- 移動フェーズに応じた解説
  - **バス停へ**: 街歩きの楽しみ方
  - **乗車中**: 車窓からの景色、沿線の歴史
  - **目的地へ**: 見どころ、参拝のポイント
- カラオケ風字幕表示
- 音声読み上げ対応

### 4. 位置シミュレーター（開発者モード）

- ルート上を仮想移動
- 速度調整機能
- デモンストレーション用途

## 👥 ターゲットユーザー・ユースケース

### ターゲットユーザー

| ユーザー層 | 特徴 | Pathの提供価値 |
|:---|:---|:---|
| **初めての京都観光者** | 土地勘がなく、どこに行けばいいかわからない | 混雑を避けた穴場スポットの提案 |
| **リピーター** | 有名スポットは行った、新しい発見をしたい | 混雑度の低い時間帯・エリアの可視化 |
| **外国人観光客** | 日本語の案内が読めない | AIによる多言語対応の可能性 |
| **高齢者・移動弱者** | 混雑した場所は避けたい | 快適なルートと明確な乗換案内 |

### ユースケース

#### ケース1: 朝イチの観光スタート

1. ホテルを出て、Pathを起動
2. 現在地周辺の「快適」スポットを確認
3. 混雑度の低い清水寺への早朝ルートを検索
4. バス移動中、AIガイドが東山エリアの歴史を解説

#### ケース2: 午後の予定変更

1. 予定していたスポットが「混雑」表示
2. 同エリアの「やや快適」スポットを探索
3. 知らなかった穴場寺院を発見
4. そのまま徒歩ルートをナビゲーション

#### ケース3: 効率的な観光プラン

1. 複数のルート候補を時間・料金で比較
2. 最速ルートではなく、車窓の景色が楽しめるルートを選択
3. 移動しながらAIガイドを聴き、到着前に予習完了

## 💻 開発環境セットアップ

### 必要要件

- Node.js 18.x 以上
- npm または yarn

### インストール

```bash
git clone https://github.com/AbeShohei/Path.git
cd Path
npm install
```

### 環境変数設定

`.env.local` ファイルを作成:

```env
VITE_OPENROUTER_API_KEY=your_openrouter_api_key
```

### 開発サーバー起動

```bash
npm run dev
```

### ビルド

```bash
npm run build
npm run preview
```
