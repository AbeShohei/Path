## 🎯 概要

『Path - Kyoto Guide』は、京都観光の「混雑」と「移動」の課題解決に特化したWEBアプリです。

最大の特長は、過去の人流データを分析した高度な混雑予測機能。エリアや時間帯ごとの混雑レベルを可視化し、快適な観光ルート選びをサポートします。
また、生成AIを活用した「AI音声ガイド」を搭載。移動中のバス車内や徒歩ルート上で、位置情報と連動してその土地の歴史や文化を物語として語りかけます。

さらに、観光ガイドに最適な**京都市バス**に特化したルート検索を開発。路地裏や歴史的な街並みを眺めながらの移動体験を最大化します。3D現在地マーカーによる直感的なナビゲーションとともに、移動時間そのものを豊かな観光体験へと変える、新しい形のスマートガイドアプリケーションです。

### コアコンセプト

| コンセプト | 説明 |
|:---:|:---|
| **Travel as a Story** | 移動時間を、AIが語る土地の物語（歴史・文化）で彩る |
| **Data Driven** | オープンデータを活用した混雑回避と正確なルート案内 |

## 💡 開発のきっかけ・背景

### 京都観光の現状

京都は年間5,000万人以上が訪れる世界有数の観光都市です。しかし、以下の課題が顕在化しています：

1. **オーバーツーリズム問題**
   - 特定の観光地（清水寺、伏見稲荷など）への観光客の集中
   - 混雑による観光体験の質の低下
   - 地域住民の日常生活への影響

2. **移動時間の「もったいなさ」**
   - バスや電車での移動時間は「空白の時間」になりがち
   - せっかくの京都の街並みを見ても、その歴史や背景を知る機会がない

3. **情報格差**
   - 初めての訪問者は、穴場スポットを見つけにくい
   - リアルタイムの混雑情報が不足

### 解決に向けた着想

> 「公共交通のオープンデータと人流データを組み合わせれば、**混雑を避けながら快適に観光できるルート**を提案できるのではないか？」

> 「さらに、移動中にAIが**その場所の歴史や文化を語ってくれれば**、移動時間そのものが観光体験になるのではないか？」

この2つの着想から、**Path**の開発がスタートしました。

## 🔍 課題とアプローチ

### 課題1: 混雑情報のリアルタイム性と相対化

| 課題 | アプローチ |
|:---|:---|
| **データの偏り** | 京都市全体の人流データを使うと、繁華街と山間部の格差が激しすぎる |
| **相対的な評価** | **観光スポットが存在するメッシュのみ**を母集団として抽出し、偏差値（T-score）を算出 |
| **季節変動の反映** | **月別・時間帯別**（朝・昼・夕）の平均データを保持し、現在の月時に合わせた予測を表示 |

**混雑度判定ロジック (実装: `services/humanFlowService.ts`)**:

観光スポットがあるエリアの人流データのみを抽出・集計し、以下の偏差値基準で5段階に分類しています。
特に、**月ごとの変動（11月の紅葉シーズンと2月の閑散期など）**を考慮するため、月別の統計データを使用しています。これにより、「今は空いている時期だが、その中では比較的混んでいる」といった、観光客の実感に近い「リアルタイムな感覚に合わせた予測」を実現しています。

- **Lv 1 快適**: 偏差値 ～42
- **Lv 2 やや快適**: 偏差値 42～48
- **Lv 3 通常**: 偏差値 48～52
- **Lv 4 やや混雑**: 偏差値 52～58
- **Lv 5 混雑**: 偏差値 58～

### 課題2: 移動体験の最適化範囲

| 課題 | アプローチ |
|:---|:---|
| **地下鉄の限界** | 地下鉄は移動が早いが、**車窓からの景色が見えない**ため「移動自体を観光にする」コンセプトに不向き |
| **バスへの集中** | あえて**「京都市バス」**に対象を絞ることで、路地裏や歴史的な街並みを眺めながらの移動体験を最大化 |

本来はあらゆる交通手段を網羅すべきですが、本アプリの「Travel as a Story（移動を物語に）」というコンセプトを体現するため、車窓からの風景情報とAIガイドがリンクしやすい**バス移動**をコア体験として設計しました。

### 課題3: AIハルシネーション（嘘）の抑止

| 課題 | アプローチ |
|:---|:---|
| **事実と異なる生成** | AIにゼロから解説を作らせると、存在しない歴史を語るリスクがある（ハルシネーション） |
| **RAGアーキテクチャ** | **京都市オープンデータの公式説明文**をプロンプトに埋め込み、AIの役割を「事実の生成」から「表現の変換」に限定 |

**AIへの指示（プロンプト設計）**:
AIには「新しい情報を付け足すこと」ではなく、以下の2点のみを厳格に指示しています。

1. **文体変換**: 「〜である」調の硬い説明文を、ガイド風の「〜ですね」調の語り口に変換
2. **平易化**: 専門用語や難解な歴史用語を、観光客でも直感的に分かる言葉に噛み砕く

これこれにより、情報の正確性をオープンデータで担保しつつ、AIの表現力で情緒的な価値を付加することに成功しています。

**実際のプロンプト（抜粋）**:

```text
あなたは京都の歴史と文化を知り尽くしたベテラン観光ガイドです。
現在、ユーザーはバスや徒歩で移動中です。[方向]に見える「[スポット名]」について、
移動中の風景がより輝いて見えるような、魅力的な語りをお願いします。

【スポット情報】
名称: [スポット名]
元の説明: [オープンデータの説明文]

【執筆のルール】
1. 200文字程度の日本語で、情緒豊かに語ってください。
2. 土地の歴史的背景、地名の由来、または季節の情景など、ガイドブックにはない「生きた情報」を一味加えてください。
3. 専門用語は避け、初めて京都に来た人でも直感的に分かるような平易な表現を使ってください。
...
```

このように、**「元の説明（事実）」をプロンプト内で明示的に与える**ことで、AIが勝手に歴史を捏造するのを防いでいます。

## ✨ 主な機能

### 1. 混雑回避スポット検索

- 現在地周辺の観光スポットを**混雑度順**に表示
- 5段階の混雑フィルター（快適〜混雑）
- 時間帯切替による混雑予測表示

### 2. ルート検索・ナビゲーション

- **バス + 徒歩**の複合ルート検索
- **京都市営地下鉄**対応
- 出発・到着時刻、乗換駅の詳細表示
- 途中駅のアコーディオン表示

### 3. AIガイド（移動中のナレーション）

- 移動フェーズに応じた解説
  - **バス停へ**: 街歩きの楽しみ方
  - **乗車中**: 車窓からの景色、沿線の歴史
  - **目的地へ**: 見どころ、参拝のポイント
- 音声読み上げ対応

### 4. 位置シミュレーター（開発者モード）

- ルート上を仮想移動
- 速度調整機能
- デモンストレーション用途

## 📊 使用オープンデータ一覧

### 公共交通データ

| データ名 | 提供元 | 形式 | 用途 |
|:---|:---|:---|:---|
| **京都市バス GTFSデータ** | 京都市交通局 | GTFS | 停留所・路線・時刻表・経路形状 |
| **京都市営地下鉄 GTFSデータ** | 京都市交通局 | GTFS | 駅・路線・時刻表 |

**本アプリでの実装（加工済みデータ）**:

元データ（GTFS）はファイルサイズが大きいため、ビルド時に必要な情報のみを以下のJSONファイルに抽出・加工して利用しています。

- `public/data/kyoto-stops-graph.json`: バス停・駅の接続関係をグラフ構造化したデータ（経路探索用）
- `public/data/kyoto-bus-routes.json`: 地図上にルート線を描画するための形状データ
- `public/data/timetables/*.json`: 路線ごとの運行時刻表を分割して格納（オンデマンド読み込み用）

### 人流データ

| データ名 | 提供元 | 形式 | 用途 |
|:---|:---|:---|:---|
| **KDDI Location Analyzer 人流データ** | 京都市オープンデータ | CSV | 1kmメッシュ別・時間帯別の滞留人口 |

**本アプリでの実装（加工済みデータ）**:

数GBに及ぶ人流CSVデータを、アプリ内で高速に検索できるよう以下の形式に集計・圧縮しています。

- `human_flow_monthly.json`: 3年分（2019-2021）のデータを「月別・時間帯別・メッシュ別」の平均値として集計した統計ファイル。これにより、オフラインかつ高速な混雑度判定を実現しました。

### 観光スポットデータ

| データ名 | 提供元 | 形式 | 用途 |
|:---|:---|:---|:---|
| **京都府観光施設一覧** | 京都府オープンデータ | CSV | 観光スポット名・位置・説明・営業時間 |

**本アプリでの実装（加工済みデータ）**:

- `services/spotService.ts`: 観光施設CSVから、「名称」「緯度経度」「説明文」等の必須項目のみを抽出し、TypeScriptの定数データとして埋め込んでいます。これにより、APIリクエストなしで瞬時にスポット情報を表示可能です。

### その他オープンデータ・API

| データ/API | 提供元 | 用途 |
|:---|:---|:---|
| **OSRM** | OpenStreetMap Foundation | 徒歩経路検索 |
| **OpenStreetMap** | OpenStreetMap | 地図タイル・地理情報 |
| **Wikimedia Commons** | Wikimedia Foundation | 観光スポット画像 |

## 🧠 アルゴリズムと創意工夫

### 1. ハイブリッド・ルート検索アルゴリズム

数千のバス停と複雑な路線網から「最適なルート」を瞬時に導き出すため、独自の2段階アルゴリズムを実装しています。

- **Phase 1: 幾何学的フィルタリング (Geometric Filtering)**
  - 全探索は計算コストが高いため、まずは出発地・目的地周辺のバス停 (半径3-5km) を特定し、「共通の路線ID」を持つペアを高速に抽出します。
  - 直線距離ベースで概算スコアを算出し、有望なルート候補をトップ8に絞り込みます。

- **Phase 2: 詳細計算 (Detailed Simulation)**
  - 絞り込んだ候補に対してのみ、以下の高負荷な計算を行います。
    1. **OSRM**: バス停までの正確な徒歩ルートと時間を計算。
    2. **GTFS時刻表照合**: 現在時刻に基づき、実際の運行ダイヤと照合。「次のバス」の待ち時間と乗車時間を正確に算出します。
    3. **翌朝検索**: 終バス後の場合、自動的に翌日の始発を案内します。

この処理を並列で行い、**ストリーミング形式**（見つかった順）でUIに表示することで、ユーザーを待たせない体感速度を実現しています。

### 2. データ処理パイプライン

オープンデータはそのままではWebアプリで扱いにくいため、ビルド時に以下の加工を行っています。

1. **GTFS → グラフ構造化**: バスの路線情報と時刻表を解析し、`kyoto-stops-graph.json`（停留所間の接続情報）と `kyoto-bus-routes.json`（描画用の経路形状）を生成。
2. **人流データ集計**: 3年分・数GBのCSVデータを解析し、**「月別×時間帯別×メッシュ別」**の平均人口データに圧縮・集計。これを `human_flow_monthly.json` としてアプリに同梱し、オフラインでも高速な混雑予測を可能にしています。

### 3. ガイドスポットの選定ロジック

移動中、次々と現れる観光スポットから「今、案内すべき場所」をどう選ぶかにも工夫があります。

- **距離優先ソート**: 現在地から近い順（Radius 50km以内）にスポットを候補として取得します。
- **レートリミット制御**: AI APIの負荷とコストを抑えるため、ガイド生成は「10秒に1回」に制限。
- **キャッシュ戦略**: 一度生成したガイドはメモリに保持し、同じ場所に戻った際の再生成（API課金）を防ぎます。
- **フィルタリング**: 「案内所」「トイレ」などの観光的価値の低いスポットは除外しています。

## 👥 ターゲットユーザー・ユースケース

### ターゲットユーザー

| ユーザー層 | 特徴 | Pathの提供価値 |
|:---|:---|:---|
| **初めての京都観光者** | 土地勘がなく、どこに行けばいいかわからない | 混雑を避けた穴場スポットの提案 |
| **リピーター** | 有名スポットは行った、新しい発見をしたい | 混雑度の低い時間帯・エリアの可視化 |
| **高齢者・移動弱者** | 混雑した場所は避けたい | 快適なルートと明確な乗換案内 |

### ユースケース

#### ケース1: 朝イチの観光スタート

1. ホテルを出て、Pathを起動
2. 現在地周辺の「快適」スポットを確認
3. 混雑度の低い清水寺への早朝ルートを検索
4. バス移動中、AIガイドが東山エリアの歴史を解説

#### ケース2: 午後の予定変更

1. 予定していたスポットが「混雑」表示
2. 同エリアの「やや快適」スポットを探索
3. 知らなかった穴場寺院を発見
4. そのまま徒歩ルートをナビゲーション

#### ケース3: 効率的な観光プラン

1. 複数のルート候補を時間・料金で比較
2. 最速ルートではなく、車窓の景色が楽しめるルートを選択
3. 移動しながらAIガイドを聴き、到着前に予習完了

## 💻 開発環境セットアップ

### 必要要件

- Node.js 18.x 以上
- npm または yarn

### インストール

```bash
git clone https://github.com/AbeShohei/Path.git
cd Path
npm install
```

### 環境変数設定

`.env.local` ファイルを作成:

```env
VITE_OPENROUTER_API_KEY=your_openrouter_api_key
```

### 開発サーバー起動

```bash
npm run dev
```

### ビルド

```bash
npm run build
npm run preview
```
